# TA 學習哲學

從三輪對抗式審查中存活下來的核心原則。

---

## 1. 這是參考語料庫，不是課程

**最大的錯誤**：把這個資料夾當成要從頭讀到尾的教材。

正確用法：遇到問題 → 來這裡找答案 → 帶著問題的脈絡閱讀。  
帶著真實問題閱讀的一小時，抵得上被動閱讀的十小時。

---

## 2. Visual nodes 先，HLSL 程式碼後

從 ShaderGraph / Material Editor 開始。節點讓心智模型變得可視化。  
理解「資料怎麼流動」之後，再寫 HLSL——你會更快，犯的錯更少。

**反直覺的真相**：從程式碼開始學 shader 的人，常常能寫程式碼但不理解在做什麼。  
從節點開始的人，常常更快理解底層發生了什麼。

---

## 3. 先 Profile，再優化

在打開 RenderDoc 或 Unreal Insights 之前，不要碰任何 shader 優化。  
你以為的瓶頸幾乎永遠不是真正的瓶頸。

**規則**：沒有 profiler 數據支持的優化，是猜測，不是工程。

---

## 4. 基礎是查找資源，不是前置課程

線性代數、色彩科學、渲染管線基礎——這些很重要，  
但**不是你開始動手之前必須完成的前置課程**。

正確心態：邊做邊查。遇到 tangent space 問題，去查矩陣。  
遇到顏色不對，去查 gamma/linear。基礎知識在有脈絡時吸收最快。

**唯一例外**：在你完全卡住、無法進展之前，先花 1-2 小時讀基礎章節的核心概念。

---

## 5. 概念先於工具，工具是葉節點

「我學了 Unity ShaderGraph」不是技能。  
「我理解 PBR 微面元模型，在 ShaderGraph 裡實作」才是技能。

引擎換了，概念留著。引擎知識是可替換的葉節點。概念是根。

---

## 6. Vulkan 是概念語言，不是必學的程式 API

大多數 TA 不需要寫 Vulkan 程式碼。  
但 Vulkan 暴露的**概念**（render pass、barrier、descriptor set 成本、記憶體階層）  
讓你能讀懂 profiler 輸出、理解引擎為什麼做出它的選擇。

**邊界**：理解概念 → 是的，必要。寫 `VkCreateInstance` 程式碼 → 只在特定情境需要。

---

## 7. TA 的核心能力是翻譯

在美術意圖和工程成本之間翻譯。  

這意味著：
- 能把「這個 shader 每 frame 多花 0.3ms」翻譯成美術師聽得懂的代價
- 能把「我要這個材質看起來像濕石頭」翻譯成工程師看得懂的技術需求
- 能說「這個效果值不值得這個成本」，而不只是「能不能做到」

---

## 8. 作品集驅動學習

每學一個概念，問自己：「這可以做成什麼可展示的東西？」  
看每個章節的 `project-ideas.md`——那裡的練習有真實的生產約束（平台、ms 預算、polygon 限制）。

沒有作品集，知識就只是知識。
