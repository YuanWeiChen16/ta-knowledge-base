# 06 — TA 角色與思維

**穩定性標籤**：`[STABLE]`

---

## TA 在製作團隊中的位置

```
美術部門 ←→ [Technical Artist] ←→ 程式部門
         翻譯意圖           翻譯成本
```

TA 是橋樑，不是任何一邊的附屬。

---

## TA 的三種核心工作模式

### 1. 火線救援（Firefighter）
美術師遇到卡關 → TA 找到技術解法或替代方案。  
**心態**：先理解美術意圖，再找技術路徑，不要直接說「不行」。

### 2. 工具建造（Toolsmith）
識別美術師重複在做的事 → 寫工具自動化。  
**黃金問題**：「這個操作一週要做幾次？」超過 3 次就值得自動化。

### 3. 系統設計（System Designer）
在製作前期定義材質規範、命名規範、LOD 規格、效能預算。  
**影響力最大但最不可見**。早期 1 小時的規範設計，能節省後期 100 小時的修改。

## 初級 vs 高級 TA 的思維差距

| | 初級 TA | 高級 TA |
|--|---------|---------|
| 遇到問題 | 找有沒有人遇過同樣的問題 | 從第一原則推理解法 |
| 看一個 shader | 這個 shader 怎麼做 | 這個 shader 在整個 pipeline 中的位置 |
| 工作範圍 | 被分配到什麼，做什麼 | 預見即將出現的問題，主動解決 |
| Shader 閃爍 | 加 bias（治症狀）| 找精度根因（治病因）|
| 收到需求 | 照做 | 先問「為什麼」，提出更好方案 |

## 溝通模式（TA 最被低估的技能）

### 和美術師溝通
- **先問意圖**：「你希望這個材質傳達什麼感覺？」
- **用視覺語言**：不說「alpha blending expensive」，說「超過 3 層半透明，行動裝置幀率會掉 10fps」
- **給替代方案**：不只說「這個做不到」，說「直接做太貴，但用 [X 方法] 可以達到 80% 效果，成本低 10 倍」

### 和程式師溝通
- **用數字**：「這個 pass 多 0.8ms」比「慢了一些」更有用
- **已排除選項**：說明你已經試過什麼、為什麼不行
- **提供最小可驗證範例**：重現問題的最小場景
